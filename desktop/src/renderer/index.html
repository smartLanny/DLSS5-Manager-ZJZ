随程序提供

完整组件与更新包有什么区别？

完整组件目录用于首次安装与修复，标准 OTA 或单个 addon 用于更新。这里选择的是安装文件来源；安装后的插件仍由游戏内 ReShade 加载。切换来源不会立即改动游戏，版本更新需按游戏应用并保留恢复记录。

导入核心更新

标准 OTA 会一起校验核心和配套组件；单个 addon 只更新核心。DX11 的兼容桥接按 API 自动部署，DX12 保留所选核心及共用组件。

0.3 稳定基线，0.4 Beta

核心版本与管理器版本分别记录。实验分支的构建结果不能代替具体游戏验证，实际可用版本以上方组件目录为准。

按游戏选择与回退
0.1

先增强，再交给游戏超分

游戏以 1440p 渲染 → NR 增强 → 游戏自己的 DLSS SR → 4K。

NR 处理 1440p；放大到 4K 仍由游戏原生 DLSS SR 负责。第一次证明“先 AI 增强，再超分”可以跑。
0.2

把增强结果合回原图

NR 处理后，把变化合回原始画面，再交给游戏原生 SR。

仍以 1440p 做 NR，重点解决 HDR、颜色和合成问题。开始处理画面合成和 HDR 兼容。
0.3

让 NR→SR 更稳定

仍是“NR → 游戏原生 SR”，但迁移 NR 效果的过程更稳。

NR 处理 1440p；最终放大到 4K 由游戏原生 SR 负责。NR→SR 开始真正工程化、稳定化。
Beta0.4

NR 可以单独用更低分辨率

游戏保留 1440p → 额外缩一份 1080p 给 NR → AI 修改贴回 1440p → 游戏原生 SR → 4K。

NR 实际处理 1080p，和游戏自己的渲染分辨率解耦。核心飞跃：降低 NR 成本，同时保留游戏原生超分。

当前 NR 安装路线要求 64 位及已有普通 DLSS；DX11 需要配套桥接，DX12 直接使用核心。Vulkan、DX9/DX10/OpenGL 等仍需后续兼容实现，界面可选不代表已经支持。
