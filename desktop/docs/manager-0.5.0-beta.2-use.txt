DLSS 5 AI 超分管理器 0.5.0-beta.2 · 精简管理器测试版

管理器本体与大型 NVIDIA NR Runtime 已拆分。安装版、单文件便携版和免安装 ZIP 功能相同；RTX40、RTX50、40+50 合并运行库以独立 DLC 提供。这仍是候选包，不是已经覆盖所有游戏与显卡的稳定版。不要覆盖你唯一的旧管理器或唯一的游戏备份。

一、第一次启动

1. 推荐使用安装版并把安装目录选到 D 盘；免安装 ZIP 要完整解压到非系统盘后再运行。单文件便携版会由 Electron 临时展开，C 盘紧张时优先安装版或免安装 ZIP。
2. 双击“DLSS 5 AI 超分管理器.exe”或安装后的快捷方式，一般不要使用管理员身份。
3. 如果双击后没有窗口，先确认任务栏没有已打开的管理器，再运行“兼容启动.cmd”；仍失败时运行“启动诊断.cmd”，把生成的脱敏反馈 ZIP 发给维护者。不要关闭杀毒软件或添加全盘排除。
4. Windows 显示未知发布者时，先核对本包 SHA-256。本测试包未使用不能建立公众信任的本机自签名证书。

二、先做安全基线

1. 打开一款已经能正常运行的游戏，只查看，不安装新组件。
2. 如果游戏目录已有 Core、但旧管理器没有留下本版可识别的回执，游戏卡片应显示“已有插件待确认 / 检查已有安装”，不能显示成普通“支持安装”。打开后 Core 必须保持“请选择”，不能自动选 0.4.7。
3. 明确选择一个目标 Core 后点“预览已有安装处理”，逐项核对旧文件的备份与替换路径；先取消，确认游戏目录没有发生变化。只有再次预览并确认应用，才允许把旧文件备份到 _DLSS5_Backup 后替换。
4. 确认真正的新安装默认 Core 是 0.4.7beta；已有受管游戏固定的 Core 不应被自动换成 D21。
5. 在“维护”页从游戏 A 切换到游戏 B，完成一次查询。随后点“打开游戏目录”和“保存反馈”，只能针对游戏 B，不能再打开或保存游戏 A。
6. 缩放 Windows 到 200%，把窗口缩到约 960×520，确认侧栏可以滚动，游戏、增强、维护、组件库入口都能到达，页面没有横向截断。

三、Core 与组件

本包实际可用：0.2.0-beta.2、0.4.2、0.4.7beta、0.5 D21 累计常规版。0.4.7beta 是默认项；D21 会显示为显式测试项，不会自动替换旧游戏选择。新游戏既可沿用默认 0.4.7，也可由用户在预览前直接选择 D21；选择 D21 仍会完整安装已校验的 ReShade、Runtime、Core、nrchain 与配置配套。

精确 0.3.3.4 和 0.4.7 Corefix8 原文件尚未取得，因此菜单会明确显示“组件未准备”。绝不会拿相近版本改名代替。拿到与登记摘要完全一致的原包后再补入，不影响现有四套 Core 的测试。

Core 和同源 nrchain/config 作为一个整体导入、预览、安装与恢复；不允许只换其中一个文件。DX12 原生路线使用 Core + 显卡运行库，不安装 Bridge 或 Feeder；DX11 的默认 0.4.7 Core 自动配套固定适配版 DLSS5 Bridge 1.4.12；没有原生 DLSS 输入的路线使用 DLSS5 Feeder 及其专用配套，不再叠加 Bridge。官方 Bridge 1.4.13-pre8、Feeder 0.15.1、Vulkan Provider 和 legacy host 已随包登记为候选组件。Bridge pre8 只供显式选择测试，不会替换 0.4.7 的固定 1.4.12 配套，也不代表已通过所有游戏兼容验收。

大型 NR Runtime 不放进精简管理器。首次启动时若看到“还差一份显卡运行库”，直接点“立即导入运行库 DLC”即可；也可进入“组件管理 → 导入运行库 DLC”。RTX40 用户选择 NR-Runtime-RTX40.zip，RTX50 用户选择 NR-Runtime-RTX50.zip；需要同时准备两套时可选择 NR-Runtime-RTX40-RTX50.zip。无需手动解压，管理器会自动启用与当前显卡匹配的一套；合并包不会把两个同名 DLL 同时写进游戏。

普通 ReShade Add-on 与 Core 分开管理：到“组件管理 → 导入 Add-on / 组件”选择 64 位 .addon64，导入只进入组件仓库，不会立即修改游戏；再展开目标游戏，到“高级与维护 → 用户 Add-on”按游戏加载。例如 renodx-dlss-26091112-zh.addon64 会作为 RenoDX 用户模块保存，不会改名或冒充 NR Core。若游戏目录已有同名但摘要不同的文件，管理器会停止而不是覆盖；移除时也只删除由本管理器部署且未被外部修改的文件。

Steam 游戏默认使用“自动 · Steam 优先”；可在“高级与维护 → 加载与启动”改成“直接启动 EXE”。游戏卡片右侧第一个按钮始终是启动，改名位于展开后的“游戏条目”。

四、RTX 40 系补帧（重点）

旧 MFG Unlock 0.7 不再作为安装或回退选项。本包只提供官方 MFG Unlock 0.9，来源：
https://github.com/mavismmg/MFGAdaUnlock-RenoDx/

第一次请保持推荐值，每次只改一个选项，先“预览”再“应用”。如果游戏卡死或不能启动：退出游戏，在维护页恢复/隔离 MFG 组件，再启动原游戏；管理器不得为了可选补帧阻止游戏启动。记录显卡型号、驱动、游戏、API、Core、修改项和发生卡死的步骤。

超分和补帧设置分别拥有自己的预览、收据和恢复边界。切换游戏后，草稿不能串到上一款游戏；未点击应用的设置不得随启动自动写入。

五、插件清理与恢复

“仅清理管理器安装项”只删除有收据且摘要匹配的文件，保留用户自己放入的 DLL。“扫描第三方图形插件”会先列出未知 ReShade、RenoDX、Bridge、Feeder、代理 DLL 和 sidecar；选择“隔离”时移入可恢复区，不直接永久删除。先看预览，再确认；游戏运行时不要清理。

清理后分别验证：游戏可以原样启动、管理器显示无待恢复事务、隔离项目可以恢复。外部文件在安装后被修改时，管理器应停下并提示，不得静默覆盖或删除。

六、减少 C 盘占用

解压在非系统盘时，新建的大型组件仓库默认跟随程序所在盘。已有仓库可在“组件库”使用“移动仓库”：选择新目录后完整复制并逐文件校验，重启管理器才切换并清理旧副本。迁移中断时继续使用原仓库，不应留下半套库存。

不要手动删除仍有安装收据、恢复记录或隔离项目的仓库。反馈 ZIP 不收集大型组件和完整游戏文件。

七、推荐实测顺序

1. 普通双击启动，再测兼容启动；确认都不是管理员令牌。
2. 测“游戏 A → 游戏 B → 查询 → 打开目录/保存反馈”，确认只作用于 B。
3. 用一款已知正常的 DX12 游戏依次测 0.2、0.4.2、0.4.7，再恢复原状态。
4. 用一款全新 DX12 测试游戏直接选择 D21 完成预览、安装和卸载恢复；再在已安装的 0.4.7 基线上更新到 D21 并恢复基线。不要把 D21 的结果推定到其他 Core。
5. RTX 40 先不启用 MFG，再启用 MFG 0.9 推荐值，最后一次只改一个参数；遇到卡死立即恢复 MFG。
6. 分别测试“仅清理管理器项”“隔离第三方插件”“恢复隔离项”。
7. 有完整配套时再测试 DX11 Bridge、Vulkan、Feeder、HoYoShade；米哈游路线继续绑定原启动器，不改成直接 EXE。
8. 最后移动组件仓库到非系统盘，重启并验证已有 Core/runtime 仍可识别。

请反馈：游戏名、显卡、驱动、Windows 缩放、API、Core、Provider、启动方式、成功/失败步骤，以及“启动诊断.cmd”生成的脱敏 ZIP。画质、帧率、卡死和界面卡顿分开记录。
