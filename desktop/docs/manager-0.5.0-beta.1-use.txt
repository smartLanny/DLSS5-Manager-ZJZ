DLSS 5 AI 超分管理器 0.5.0-beta.1 · Core / Provider 组件测试版

本版使用随包登记的当前 Core 身份和组件清单。请先退出游戏，再启动管理器；首次安装、切换和恢复都会先生成预览，确认后才修改游戏目录。

安装包和运行库
基础包包含 Electron 管理器、当前 Core、NR chain、ReShade layer、MFG Unlock 0.9、HoYoShade/loading-helper/REFramework 小资源，以及 staging 中登记的 Bridge/Feeder/Vulkan Provider 候选。基础包不包含大型 NVIDIA NR runtime。

离线整合包在基础包上附带 RTX20–40 共用的 RTX40 族运行库和 RTX50 专用运行库。也可以在“组件库”中分别导入对应的运行库 ZIP；导入后 Manager 只按文件摘要、位数和显卡族登记，不会把运行库直接写入游戏目录。请保留旧版本缓存和收据，不要用同一个组件 ID 覆盖不同文件集合。

Core、Provider 和 API 匹配
Manager 按当前游戏 API、游戏位数和已识别硬件族选择路线。DX9/DX10/DX11/DX12/Vulkan Provider 必须有自己的 component-manifest.json 和 external-provider-package.json；当前 Core 必须声明 NRExternalProviderV1 所需能力，并提供同源 nrchain_nvngx.dll、nr_before_sr.ini。Provider 不携带这些 Core/chain/runtime 文件，它们由当前 Core/Runtime 库存注入。

稳定 OF、legacy host 和 Vulkan Provider 默认只登记为候选；preview OF 默认关闭，需要在组件库中手动选择。AMD OF 是实验路线，默认不启用 AMD 100/50 组件；NVOF 当前没有编译。所有 Provider 的 file SHA-256、许可证和内部清单都会保留，候选状态不等于具体游戏兼容。

DX11 Bridge
当前 Bridge 支持 completion auto、async、sync 三种策略，默认 auto。auto 在等待异常后可以保持 sync，sync 只等待队列继续推进；该逻辑用于避免 D3D11 首次异步复制停滞。Bridge 当前仍是候选包，completion 变更尚未完成 fixture、GPU、游戏和性能验证；遇到画面停滞、输出缺失或异常回退，请停止游戏并用 F8 收集反馈。

安装、切换和恢复
1. 在游戏卡片选择 API、Core/Provider 和路线，先查看预览中的文件、目标位置与摘要。
2. 关闭游戏后确认操作。Manager 会保存事务、备份可恢复文件并记录安装收据；失败时保留恢复记录，不覆盖未确认的外部文件。
3. 需要更换路线或 Provider 时，先执行当前路线的恢复，再选择新路线。自动回退只在本次运行向后尝试，不覆盖用户保存的起点。
4. 如果管理器或系统在操作中断，重新打开后先处理“需要恢复”的事务。恢复完成前不要手动删除备份、组件库存或游戏目录中的收据。

F6 仍是 NR 总开关。关闭后 Manager 不再新增 NR、输入复制或辅助处理，只收尾已经在途的工作。MFG、ReShade 和 Provider 的恢复均按收据中的原始 provider ID 与文件摘要执行。

验证边界
本版的文件身份、组件清单和 Manager 事务边界可以在本地核对；Core、Bridge、Feeder/Vulkan Provider 及具体游戏的真实画面、驱动组合、GPU、性能和长时间稳定性仍需独立验收。未完成验收的候选不会因为被随包登记而变成兼容结论。
