# 新界面合并与旧安装验收

目标：保留 PR #5 的新界面，修复预览定位、小窗口侧栏和名称输入框回归；不借 UI 更新重装游戏组件。
本次不修改 NR 仓库、渲染算法、桥接器二进制、HoYoShade 启动器绑定或安装事务协议。

## Core 选择

基础菜单依次展示 0.2 初版、0.3.3.4 稳定版、0.4.2、0.4.7、0.5D21 多层叠加版。
菜单只引用真实 inventory ID，缺失的版本标为“组件未准备”并禁用。显示名不能证明版本或兼容性。
已安装版本、已有默认身份、手动导入版本和桥接对照元数据保留；缩短菜单不删除任何文件或恢复来源。

已核验完整 D21 组件目录可通过 `prepare-core-catalog.js` 设为新安装默认，前提仍包括完整 Core/chain/INI、哈希和输入接口检查。
仅 Core 更新补丁不能成为完整安装默认。D12/D20 不会因为名称相似变成 D21；D21 未准备时保留原有完整默认，不降级。
公开源码没有附带这五套 Core 二进制，本次不能宣布已经内置或实机验证 D21。D21 成品的实际 ID、清单和 SHA-256 应由独立发行阶段提供。
新菜单不改写 settings.json 的已保存选择；既有游戏仍以自己的安装记录为准，切换须预览、明确应用。

## 自动检查

`Desktop integration` 工作流检查共享合同、源码无载荷、vendor、HTML/renderer ID、配置保留、Core 菜单、包默认、旧版本切换和篡改拒绝。
随后运行普通 GamePage 和 HoYoShade 受控 Electron 流程、900×620 到 1440×900 的侧栏/输入框/长页面预览回归，最后构建并校验外部组件版。
HoYo Core 测试需要代码固定的公开 ReShade 6.8 DLL：仅下载官方固定安装档并核对安装档和 DLL SHA-256，解包而不执行；不加入源码或验证应用分发。

## 给维护者的实机验收

先保留旧管理器程序和完整组件目录，用新的 portable 验证包测试，暂不让 external 安装包覆盖唯一的旧组件来源。
外部组件版没有 NR/Core/桥接器的成品载荷，不能用“能打开界面”代表整包已准备。已有外部源路径保持不变；原来仅随旧程序提供的组件，先选择保留的完整目录再验收。

1. 旧管理器升级：游戏列表、自选 EXE/API、Core 版本、外部来源、INI、HoYo 启动器绑定和恢复记录应保持。
2. 原生 DX12、DX11 Bridge、Vulkan、Feeder 各选代表游戏。核对预览文件清单；安装后分别确认 ReShade、Core、NR 和实际画面，不把文件存在算作运行成功。
3. HoYoShade：从已绑定启动器启动，不改成直接 EXE；核对原配置、helper、取消等待和失败恢复。
4. 旧 Core → 已核验 D21 → 原 Core：每次退出游戏、预览后应用，确认旧 INI 和完整配套；验证失败回滚与卸载恢复。
5. 长列表、小窗口、浅/深色、动画开/关；所有风险说明、路径和确认按钮应可查看。记录扫描耗时、界面响应和游戏帧率分别比较。

发现问题先保存脱敏反馈和 F8 运行证据，不直接删除 dxgi.dll/d3d12.dll，也不混装多个桥接器。
