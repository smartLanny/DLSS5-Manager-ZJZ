# DLSS5 Manager 0.5 RC 中文测试说明

此文档用于私有 RC。通过源码单元测试不等于已通过显卡、游戏或启动器实测；失败项修复后必须重跑对应场景。正式发布还受精确 `0.3.3.4` Core 与公开审计门禁约束。

当前私有 RC 已包含 `0.2`、`0.4.2`、默认 `0.4.7beta` 和可手选 D21，但尚未包含精确 `0.3.3.4`。这不是用其他文件替代：正式发布门禁会明确阻断发布，直到取得 652288 字节、SHA-256 为 `2869d7d6b2d184b4200c3eb7ac671db0299be64e7625c4f816ee26b41890bfb9` 的原文件。当前 RC 可先测试其余界面、组件、路线、维护与启动器功能。

本地 `Full-RC.zip` 内只有四个独立 ZIP。Portable 解压后直接运行；RTX40/RTX50 DLC ZIP 可在组件管理中直接导入；RenoDX ZIP 需先解压，再选择其中的 `.addon64`。Windows VC++ x64 运行库不在 Full 内，缺少时按管理器提示前往微软官方页面安装。

## 1. 启动与便携目录

1. 把整个 Portable.zip 解压到非系统盘，双击主程序，不要先用管理员身份。
2. 确认窗口、任务栏和 EXE 使用同一个图标，任务栏不会出现第二套空白/旧图标。
3. 首次启动后确认程序旁出现 `data`；组件、更新、日志和 Chromium 缓存不应大批写入 C 盘 `%TEMP%`。
4. 日志最多保留 10 个，每个不超过 5 MB；下载完成后只保留当前版和一个回退版。
5. 缺 VC++ x64 时，应出现简洁应用内提示和微软官方页面按钮；损坏的本地 DLL 应提示重新解压，而不是误报缺运行库。
6. `--no-sandbox` 不是默认参数，包内也不再提供让用户自行猜测的兼容启动脚本。只有程序实际捕获到 Electron 子进程 `launch-failed/integrity-failure` 时，错误框才显示一次“临时兼容重试”；该参数不会保存或写进快捷方式。

## 2. Core 与路线解析

全新游戏默认必须是 `0.4.7beta`。当前 RC 中 `0.2`、`0.4.2` 和 D21 均可见；D21 只能手选，已有安装不能自动迁移。取得精确 `0.3.3.4` 后再补测它可见、可选且身份摘要正确。

分别预览以下路线，界面显示的 Core、API、路线与理由必须和安装/启动实际使用的一致：

- DX12 + 可用原生输入：Native，不装 Bridge 或 Feeder。
- DX11 + `NGX-D3D12-Feature1` Core：优先兼容的 DLSS5 Bridge。
- Vulkan + 兼容 Core：只有同时准备好 NIGos Bridge、ReShade Vulkan Layer 与可部署 Profile 时才走实验 Bridge；仅有 `.addon64` 不算可部署，否则使用已声明匹配 Core 的 Feeder 配套。
- 无原生输入、但有 `NRExternalProviderV1` 配套：DLSS5 Feeder 与它自己的匹配 Core。
- D21 + DX11：允许实验 Bridge。D21 + Vulkan 只有完整 Bridge Profile 到位时才允许实验 Bridge；否则界面必须显示实际 Feeder 配套 Core，不能把 D21 与 Feeder 硬拼。
- API 不确定或契约不匹配：停止预览，要求用户确认，不静默安装。

让 Bridge 启动失败一次，确认保留 Core/API/Bridge/日志证据并显示“一键改用 Feeder”；文件不得在崩溃后被悄悄替换。

## 3. 已有安装与卸载

在 Cyberpunk 2077 放置一套未受管 0.5/旧插件，重新检查后必须显示“未受管安装”，不能当作全新安装。依次验证：采用现有文件、备份后替换、仅移除管理器安装项、预览后清理未受管插件。

所有删除都要来自安装清单。修改一个已由管理器安装的文件后再卸载，管理器必须停下并保留文件，不能按文件名强删。Shadow of the Tomb Raider 与 WUCHANG 分别测试覆盖、失败反馈、自动回滚和再次重试。

## 4. 组件管理与导入

默认页面只显示：AI 增强 Core、DLSS5 Bridge、DLSS5 Feeder、40 系多帧生成、NR 运行库、RenoDX Add-on。普通用户视图不出现“图形桥/输入桥/缓存候选”等内部名称；缓存路径只放在高级详情。

逐项导入：目录、合法 ZIP、单 DLL、`.addon64`、损坏 ZIP、伪装 ZIP、未知 ZIP。只有完成架构、身份、摘要和契约校验的项目才显示“可用”；未知包只能显示“自定义候选、尚未验证”，不能直接成功或自动安装。

缺组件弹窗必须直接说明“缺少什么、用于什么”，并有“导入组件”“前往组件管理”按钮；不能显示截断的内部构建路径。RenoDX Add-on 可命名、切换和对比，同一游戏只保留一个活动 Add-on。

## 5. MFG 与超分界面

RTX40 默认测试 MFG 1.0，0.9 仅作明确回退，菜单中不得出现 0.7。安装/更新后先重启游戏一次，再评价卡顿和画质。

模型文案应为：M“均衡推荐”，L“画质优化、帧率最低”。“保持游戏原设置”与“NVIDIA 推荐档位”要有直白解释。深色模式下拉框使用深灰色，不出现白底闪烁。

只改变一个模型或倍率时，预览只列这一项；底层 `set-dword` 收在技术详情。点击后 100 ms 内出现圆形进度和当前阶段，主线程保持可操作；耗时操作可以安全取消。

## 6. 游戏卡片与每游戏隔离

卡片主操作只能是“启动游戏”和“设置”。改名、移除、打开目录位于展开后的“游戏管理/维护”。

在游戏 A 完成维护查询后切到游戏 B，再执行“保存反馈”和“打开目录”；只能作用于 B。两个游戏的草稿、忙碌状态、错误、反馈和目录不能串。展开卡片不应闪烁或导致列表重排；未知 Steam 名称显示 EXE 名而不是裸 AppID。

仅修改启动方式时，目标 300 ms 内保存，不触发全量扫描或哈希。部署、扫描和哈希无论耗时多久都要显示阶段进度。

## 7. 启动器适配

- Steam：默认官方 Steam 启动，高级设置可改直接 EXE；不默认改写 `localconfig.vdf`。
- HoYoPlay/Starward：从有效快捷方式读取 `--game=<gameBiz>`，正确发现米哈游目录和图标，启动官方入口并等待真实进程。
- 鸣潮：使用官方 launcher 与 Shipping EXE，默认保留官方 DX12/RHI 配置，不乱加参数。
- Neverness：只改白名单内 `[Game] Dx11`，不收集账号内容；一次启动失败不能锁死安装和下次重试。
- 燕云十六声：同步 `setting.ini` 与两个 API tag，验证启动器和游戏跨盘。
- WeGame：打开官方客户端并等待真实进程；无本机/官方证据时不伪造直启协议。

手动添加游戏时选择的 API 应直接成为 `preferredApi`，应用后形成 `effectiveApi`，展开设置不再重复询问。启动失败只留记录，不阻断维护、安装或再次启动。检测到 ACE、PGameProtect、HoYoKProtect、EAC、BattlEye、EAAC 时坚持官方启动，只提示风险，不绕过。

## 8. 实机矩阵与反馈

至少完成：Cyberpunk 2077 DX12 原生、一个 DX11 Bridge、一个 Vulkan Bridge、一个 Feeder 游戏；Neverness、鸣潮、燕云十六声、绝区零、WeGame；MFG 1.0/0.9；RenoDX Add-on 切换；RTX40 与 RTX50 DLC 分别导入。

每次记录管理器版本、游戏、显卡、驱动、API、Core、Native/Bridge/Feeder、MFG、启动入口、操作耗时、是否成功和恢复结果。画质、帧率、卡死、启动失败和界面卡顿分开记录。反馈包只含脱敏诊断和本次游戏身份，不含账号、完整配置、私有 DLL 或其他游戏路径。

## 9. 发布结论

只有以下条件同时满足才可发布：自动测试通过；上述维护者实机冒烟通过；精确 `0.3.3.4` 到位；公开审计无问题；最终 Portable.zip 与 `update-manifest.json` SHA-256 已记录。任何一项失败都修复并重跑，不发布半成品。
