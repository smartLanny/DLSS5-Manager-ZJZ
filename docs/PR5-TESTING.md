# 新 UI 验证包：先测这些

这是供维护者验证新界面和旧配置兼容性的候选包，不是已经完成全部游戏验收的稳定版。

## 启动前

关闭旧管理器，保留旧程序、完整组件目录和配置备份。把验证包解压到新目录，不覆盖原来的唯一副本。

优先运行带 `external-portable.exe` 的程序。它是真实管理器，不是模拟界面，但不含五套 Core、NR 运行库和完整桥接配套。已有组件通过“组件管理 → 安装组件来源”选择。没有配套时，相关安装或助手启动仍不可用，不要将此误当作已经测试通过。

portable 不代表设置完全隔离，正常启动可能读取已有的管理器配置。需要验证升级时先备份已有设置；只看界面时可以用不同 Windows 测试账号。

Windows 或安全软件提示未知发布者时，先核对来源、提交记录和 SHA-256；不要关闭杀毒、添加全盘排除或跳过签名风险提示。本候选不宣称具有代码签名。

## 自动验证不等于实机验收

包内 `BUILD.txt` 记录源码提交，`SHA256SUMS.txt` 记录 EXE 校验值，`STARTUP-STATUS.json` 单独记录打包后的普通权限启动是否实际完成。

若启动状态为 `not-run`，说明 GitHub 托管机没有普通权限桌面 Shell，安全守卫阻止了该项检查。不能把流水线通过理解为此项已通过。请在正常 Windows 桌面直接双击验证包，不要使用“以管理员身份运行”；出现无法启动或权限提示时保留日志，不要关闭守卫。该候选仍需维护者确认正常启动。

HoYoShade 的控制流程已保留，但 external 包没有完整的加载助手 / HoYoShade / 桥接器发行资源。仅选择旧 Core 来源不能自动补齐所有助手文件；这类实际游戏启动应继续用原完整配套，待整合发行包准备后再验收。

## 推荐测试顺序

1. **先不安装任何东西**：确认程序能正常打开，旧游戏列表、自选 EXE / API、Core 版本和安装组件来源仍在。已装 D12 的游戏应保留 D12，不能自动变成 D21。
2. **检查界面**：切换浅 / 深色和动画开 / 关；缩小到 900×620 和 1000×620，试添加 / 重命名、侧栏底部入口和长详情预览。先取消预览，确认没有执行更改。
3. **测试一款原本可运行的离线游戏**：先用原 Core 和原配套启动，确认不是升级 UI 后才失效。随后再做一次小设置修改、预览和应用。
4. **分别检查其他路线**：DX11 Bridge、Vulkan、Feeder 和米哈游 HoYoShade 各选已有完整配套的代表游戏；缺少助手等资源时先保留原软件，不把缺包当作加载通过。米哈游继续走原启动器绑定，不改成直接 EXE。
5. **最后换 Core 和测恢复**：只有完整 D21 成品已准备且通过预检后，才测试旧 Core → D21 → 原 Core。每次退出游戏，核对配套和配置，最后确认恢复可用。

新版菜单有五个主要版本方向；缺失版本会禁用。D21 成品未准备不允许用 D12 / D20 改名冒充，代码和界面测试不代替 D21 成品验收。

## 记录结果

写下游戏名称、显卡、接口、Core、桥接器版本、启动方式、成功 / 失败步骤。扫描耗时、界面卡顿和游戏帧率分开记录；画质用同场景开关对比。

故障后先保留脱敏反馈和 F8 证据，不连续重装，不删除未知 DLL。技术验证范围及兼容性矩阵见仓库 `docs/PR5-INTEGRATION-VALIDATION.md`。
