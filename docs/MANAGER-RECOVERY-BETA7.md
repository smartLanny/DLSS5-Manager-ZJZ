# Beta7：外部文件改动后的恢复出口

本批从本地 Beta6 `50f6e3f23c70c2d1df0fb7c74e1b8d6f1c803b18` 隔离接续，保留 Unified5 自动配套；仅修改 Manager。默认 Core 仍为 0.4.7beta，现有 Core、Bridge、Feeder 字节不变。未推送、发布、合并或操作真实游戏文件。

## 已核实的故障

Beta5 反馈的 `DEPLOYMENT_FILE_CHANGED` 来自外置部署严格校验 `ReShade.ini`：外部改动使路径读取失败，清理预览和诊断也复用了这条读取路径。此状态未必存在未完成事务，重复点击恢复不能修好绑定。`LIBRARY_RESTORE_FIRST` 又禁止保留文件移出条目，形成无出口。

## 修复

- 外置部署增加独立只读预览及明确确认：修复原运行目录、归档并清理受管环境、处理被外部改过的未完成部署。
- 目标仅来自已校验的部署记录/WAL，不跟随被改 INI 指向未知目录。先存当前字节与路径映射，再执行；个人配置、无关文件、原始历史备份保留。补齐文件必须匹配受管摘要，损坏快照不能当作来源。
- 中断事务发生外部改动时，先归档外部字节和旧 WAL，再持久化明确确认的回退映射；中途失败，下次仍可继续原恢复。
- 清理后的旧目录保持不动，后续首装创建新的代次目录；未知插件不再因为仍留在旧目录而阻止重装。
- “只移出游戏库”确认后取消待应用请求、归档条目与恢复位置；保留游戏文件、WAL、EXE 绑定和偏好。重加不会重放旧排队请求，也不会伪称已卸载。
- 普通与米哈游共享恢复预览。轻量页面摘要同样包含恢复入口，避免并行刷新覆盖；诊断保留错误与可用出口。组件更新/下载失败显示组件类别及原始错误码。

原有启动/安装完整性门槛仍有效。文件变更仍需游戏退出；真实并发写入、损坏记录、链接和未知目录不自动接管。外置目录含独立补帧恢复记录时，先修复绑定并恢复补帧，再清理；仅移出库不受这些旧恢复门槛阻塞。
